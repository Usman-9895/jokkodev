2. Activation SESSION/TOKEN confirmée par les captures utilisateur : rôle restreint, simulation réussie, premier passage manuel réussi sans donnée éligible, timer active/enabled. Le premier passage planifié reste à observer. Actualiser la notice pour ces deux catégories effectivement activées ; les autres traitements et les procédures LWS/journaux/copies externes restent séparés.
3. Clarifier les contrôles CI, l’alerte de dépendance et le dossier de licences final ; garder la réponse SystaLink en preuve sans la généraliser à des composants non examinés.
4. Effectuer les contrôles d’accessibilité et de réception utilisateur manquants. Vérifier les introuvables HTML 200/API 404 documentés et les limites des parcours incertains, sans déclarer ces défauts résolus.
5. Vérifier les conditions de soumission officielles et préparer pitch/vidéo, accès jury et dossier de preuves. Le barème n’autorise pas à ouvrir l’accès nginx ou rendre le dépôt public sans traiter séparément ces actions.
